# obs-stack

Monitoring for a Windows + WSL2 machine running a Kubernetes cluster in
[kind](https://kind.sigs.k8s.io/) on the Docker Desktop engine:

* **kind cluster `obs`** - 1 control-plane + 2 workers, pinned node image
* **kube-prometheus-stack** - Prometheus, Grafana, Alertmanager, node/kube exporters
* **Loki + promtail** - pod logs plus the WSL distro's own logs
* **Host exporters** - `windows_exporter.exe` on Windows, `node_exporter` + a
  `nvidia-smi` exporter in the WSL distro, installed as systemd units

Grafana is reachable from a Windows browser at **http://localhost:3000**, and the
dashboards show the Windows host, the WSL distro, the GPU and the cluster.

This is its own repo, self-contained: every binary, config and piece of run-time
state lives inside it, and nothing here is shared with or required by any other
project on the machine.

## Layout

```
cluster/kind-cluster.yaml       node topology + NodePort -> host port mappings
scripts/                        the whole "as code" surface (see below)
exporters/windows/              windows_exporter launcher (PowerShell)
exporters/wsl/                  systemd unit templates + host promtail config
exporters/gpu/                  nvidia-smi exporter (Python, no extra deps)
monitoring/values/              helm values for the three charts
monitoring/dashboards/          Grafana dashboards, generated by scripts/gen-dashboards.py
monitoring/scrape/              scrape config templates for the host exporters
monitoring/rules/               PrometheusRule with the host alerts
.bin/                           downloaded binaries (pinned, gitignored)
.state/                         rendered configs, probes, Prometheus data, grafana password (gitignored)
.kube/obs.yaml                  standalone kubeconfig, context kind-obs
```

## Prerequisites

* WSL2 distro with systemd running (`ps -p 1 -o comm=,` should say `systemd`)
* Docker Desktop with the Linux engine reachable from WSL (`docker info`)
* `helm` and `curl`; `sudo` without a password makes the exporter install silent
* `powershell.exe` reachable from WSL (standard on Docker Desktop + WSL)
* an NVIDIA GPU with `/usr/lib/wsl/lib/nvidia-smi` for the GPU dashboard

## Quickstart

```bash
make up        # bootstrap, cluster, exporters, deploy, targets, verify
```

Then open http://localhost:3000 in Windows and log in as `admin`. To see the
credentials that are actually in use:

```bash
make login
```

`scripts/deploy.sh` saves the password it installed into `.state/secrets.env`
(gitignored, mode 0600), so re-running deploy keeps the same login. To choose
your own password:

```bash
GRAFANA_ADMIN_PASSWORD='something-long' make deploy
```

`scripts/teardown.sh` deletes `.state/`, so after a teardown a fresh deploy
starts from the default password again.

Individual steps, in the order they need to run:

| target | script | what it does |
| --- | --- | --- |
| `bootstrap` | `scripts/bootstrap.sh` | downloads kind, kubectl, node_exporter, windows_exporter.exe, promtail, edge Prometheus; adds the helm repos |
| `cluster` | `scripts/cluster.sh` | creates or reuses kind `obs`, writes `.kube/obs.yaml`, waits for nodes |
| `exporters` | `scripts/exporters.sh` | renders + installs the WSL systemd units and starts the Windows exporter |
| `deploy` | `scripts/deploy.sh` | installs kube-prometheus-stack, loki, promtail; patches NodePorts; loads dashboards and alert rules |
| `targets` | `scripts/host-targets.sh` | probes how the cluster can reach the host exporters, renders the scrape configs, upgrades Prometheus |
| `verify` | `scripts/verify.sh` | checks every layer: pods, listeners, scrape targets, dashboards, rules, Loki labels |
| `login` | `scripts/login.sh` | prints the Grafana URL, user, password and where the password is stored |
| `dashboards` | `scripts/gen-dashboards.py` | regenerates `monitoring/dashboards/*.json` |
| `teardown` | `scripts/teardown.sh` | uninstalls everything, deletes the cluster, removes the units |

## Windows firewall

`windows_exporter` listens on `:9182` and the cluster scrapes it over the WSL
gateway. A non-elevated PowerShell cannot add the inbound rule, so run this
**once from an elevated PowerShell** (Windows side):

```powershell
powershell -ExecutionPolicy Bypass -File C:\obs-stack\windows-exporter.ps1 -Action firewall
```

Without it the cluster cannot scrape Windows directly and `scripts/host-targets.sh`
falls back to the edge Prometheus (see below), which reaches the same port from
WSL.

## How host metrics get into Prometheus

WSL2 NAT plus the Windows firewall make pod-to-host scraping unreliable, so
reachability is *probed*, never assumed:

* **pod mode** - the cluster Prometheus scrapes `windows_exporter`,
  `node_exporter`, `gpu_exporter` and host `promtail` directly.
* **edge mode** - if a pod cannot reach a port, a small Prometheus running in
  the WSL distro (`scripts/edge-prometheus.sh`, `:9190`) scrapes those exporters
  over localhost and `remote_write`s the result into the cluster Prometheus.

The outcome is recorded in `.state/host-targets.env`. Jobs whose target could
not be reached are not created at all, so Prometheus never shows a target that
cannot exist. Every host series carries `scope: host`, which is how the cluster
dashboards exclude the host exporters.

**After a WSL restart** eth0 gets a new IP: re-run `./scripts/host-targets.sh`
(and `./scripts/verify.sh`). It is idempotent.

## Dashboards

Generated by `scripts/gen-dashboards.py` from panel definitions in that file, and
shipped to Grafana by the kube-prometheus-stack sidecar (ConfigMaps labelled
`grafana_dashboard: "1"`). Regenerate with `make dashboards` and re-run
`./scripts/deploy.sh`.

| dashboard | covers |
| --- | --- |
| `obs-windows-host` | CPU per mode, memory/commit, logical + physical disk, network, TCP states, pagefile, clock drift, services, processes |
| `obs-wsl-host` | CPU, load, memory, swap, disks, filesystems, systemd units, TCP sockets, file descriptors |
| `obs-gpu` | utilisation, memory, temperature, power, compute processes, `nvidia-smi` health |
| `obs-cluster` | nodes, pods, containers, kubelet/etcd/apiserver, Prometheus/Grafana/Alertmanager/Loki health, error logs |

The datasource variables are `${DS_PROMETHEUS}` and `${DS_LOKI}`, so the dashboards
work with whatever datasource the sidecar names `prometheus` / `loki`.

## Alerts

`monitoring/rules/host-alerts.yaml` (groups `obs-host-up`, `obs-windows-host`,
`obs-wsl-host`, `obs-wsl-gpu`, `obs-log-shipping`) covers exporter availability,
CPU/memory/disk pressure, commit and pagefile pressure, disk latency, clock
drift, network errors, systemd failures, GPU utilisation/temperature/health and
log-shipping stalls. Alertmanager is on http://localhost:9093.

Stopped Windows *services* are deliberately not alerted on: `windows_service_state`
has no `start_mode` label, so "stopped" cannot be told apart from "installed but
not meant to run". The Windows dashboard shows them as a table instead.

## Logs

* pod logs: in-cluster promtail DaemonSet -> Loki (`{job="<namespace>/<app>"}`)
* WSL distro: `exporters/wsl/journal-follow.py` turns journald into JSON lines in
  `.state/journald.log`, and a WSL-side promtail tails that plus `/var/log/*.log`
  -> Loki (`{job="wsl-journald"}`, `{job="wsl-files"}`)

promtail 3.5.1's journald driver discovers no targets in this environment, which
is why journald goes through the follower script rather than a `journal:` scrape
config. Loki retention is 7 days (`monitoring/values/loki.yaml`).

## Out of scope

* **Windows event logs** - the Windows dashboard covers metrics only. Shipping
  event logs would need a Windows-side shipper (e.g. promtail on Windows pointed
  at an ETL export); nothing in this repo collects them, so no dashboard shows
  them.
* **kube-controller-manager / kube-scheduler / kube-proxy metrics** - kind runs
  those on the control-plane node bound to `127.0.0.1`, so their ServiceMonitors
  are disabled in `monitoring/values/kube-prometheus-stack.yaml`. kubelet is
  scraped; etcd is scraped because `cluster/kind-cluster.yaml` patches kubeadm
  so etcd's metrics listener binds to `0.0.0.0:2381` instead of kubeadm's
  default `127.0.0.1:2381` (that patch only applies at cluster creation, so
  changing it means recreating the cluster).

## Troubleshooting

| symptom | where to look |
| --- | --- |
| `verify.sh` says a unit is not active | `journalctl -u obs-node-exporter` / `obs-gpu-exporter` / `obs-journal-follow` / `obs-promtail-host` / `obs-edge-prometheus` |
| host jobs missing from Prometheus targets | `./scripts/host-targets.sh` (its log is `.state/host-targets.log`) |
| Windows metrics missing | elevated firewall rule for `:9182`, then `./scripts/exporters.sh windows` |
| no GPU metrics | `NVIDIA_SMI=/usr/lib/wsl/lib/nvidia-smi ./scripts/exporters.sh` and `journalctl -u obs-gpu-exporter` |
| Grafana login fails | `./scripts/login.sh` prints what Grafana's secret holds; set a new one with `GRAFANA_ADMIN_PASSWORD=<new> ./scripts/deploy.sh` |
| WSL restarted, everything broke | `./scripts/host-targets.sh && ./scripts/verify.sh` |
